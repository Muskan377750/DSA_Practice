A sorted matrix will be given to us like:- 

|10|20|30|40|
|15|25|35|45|
|27|29|37|48|
|32|33|39|50|

=====================================================================================

It is a matrix that is sorted as column wise and row wise also.
There are 3 approaches to solve this problem:-
1. Brute force approach
2. Binary search approach
3. Stair case search (Implement)

======================================================================================

1. Brute force approach:-

Key Points:-
Simple Logic: It scans the array row-by-row, left-to-right.
Early Exit: The return 1 stops the loops the exact millisecond the target is hit.
Time Complexity: O(ROWS × COLS) because it might have to look at every slot in the worst case.

=========================================================================================

#include <iostream>

const int ROWS = 3;
const int COLS = 4;

// Returns 1 if found, -1 if not found
int bruteForceSearch(int matrix[ROWS][COLS], int target) {
    // Look through every single element one by one
    for (int r = 0; r < ROWS; ++r) {
        for (int c = 0; c < COLS; ++c) {
            if (matrix[r][c] == target) {
                return 1; // Element found, exit early
            }
        }
    }
    return -1; // Checked everything and found nothing
}

int main() {
    int matrix[ROWS][COLS] = {
        {1,  3,  5,  7},
        {10, 11, 16, 20},
        {23, 30, 34, 60}
    };
    
    std::cout << "Searching for 16: " << bruteForceSearch(matrix, 16) << "\n"; // Outputs 1
    std::cout << "Searching for 99: " << bruteForceSearch(matrix, 99) << "\n"; // Outputs -1
    
    return 0;
}

================================================================================================

2. Binary search approach:-

Key Points:-
Memory Flattening: Assigning &matrix[0][0] to a pointer skips the need for row/column coordinate mapping formulas (/ and %).
Efficiency: It cuts the search space in half with every loop iteration, running in O(log(ROWS × COLS)) time complexity.
No Vector: It uses raw pointers and fixed-size dimensions, requiring zero standard library allocations.

=================================================================================================

#include <iostream>

const int ROWS = 3;
const int COLS = 4;

// Returns 1 if found, -1 if not found
int binarySearch2D(int matrix[ROWS][COLS], int target) {
    // Treat the 2D array as a continuous 1D block of memory
    int* ptr = &matrix[0][0]; 
    
    int low = 0;
    int high = (ROWS * COLS) - 1;

    while (low <= high) {
        int mid = low + (high - low) / 2;
        
        // Directly access the element using the 1D pointer
        if (ptr[mid] == target) {
            return 1; // Target found
        }
        else if (ptr[mid] < target) {
            low = mid + 1; // Search the right half
        }
        else {
            high = mid - 1; // Search the left half
        }
    }
    
    return -1; // Target not found
}

int main() {
    int matrix[ROWS][COLS] = {
        {1,  3,  5,  7},
        {10, 11, 16, 20},
        {23, 30, 34, 60}
    };
    
    std::cout << "Searching for 16: " << binarySearch2D(matrix, 16) << "\n"; // Outputs 1
    std::cout << "Searching for 99: " << binarySearch2D(matrix, 99) << "\n"; // Outputs -1
    
    return 0;
}

3. Stair case approach:-

Step-by-Step Breakdown:-
Initial Position: You stand at matrix[0][COLS-1] (top-right element, which is 40 in the example).Step Decision:If the current element is greater than the target, every element below it in that column will also be too big.
Move left (c--).
If the current element is smaller than the target, every element to its left in that row will also be too small.
Move down (r++).
Termination: The loop stops instantly if a match is hit, or if your indexes step outside the matrix boundaries.

Complexity Analysis:-
Time Complexity: O(ROWS + COLS). 
In the absolute worst case, you traverse from the top-right corner to the bottom-left corner, making at most ROWS + COLS steps.
Space Complexity: O(1). 
It uses only two variables (r and c) to track positions.
